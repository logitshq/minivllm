# Twelve fresh paired HTTP trials

Registration requires source-matching guarded CPU tests. No server, service
operation or device trial is performed by the registrar. The prepared `formal.py` specifications
remain unchanged: C1/C8, three OFF/ON pairs per C, eight warm requests and 64
formal requests per fresh server (96 warm + 768 formal requests total).

`owner.py` awaits the runner in its own process and retains the actual server
`Popen`; there is no GPU grandchild wrapper. OFF is the frozen original native
entry. ON is the frozen route entry with both tracing observers disabled. The
startup installation identity is not proof of a formal compiled invocation.
The existing captured-history audits qualify representative histories, not all
future arrival schedules. Only the completed independent formal audit can
approve the observed timing points.

The exact existing deadlines are ready120/request600/warm720/formal2400/overall3300,
close10, TERM15, KILL15 and resource5 seconds. Twelve trials produce a 40524-second
owner hard bound; this is a registration limit, not a speed prediction. Every
request and group has its existing absolute deadline. Failure stops the next
trial; known children still require wait/reap, PID absence and listener absence.
Unknown Popen outcomes do not receive a no-child proof. Recovery can follow a
failed experiment only after the recorded terminal chain is verified.

The controller keeps the actual source identity and worker entry. Four reviewed
recovery/proof code objects use explicit independent dependency dictionaries;
no imported globals, `HERE`, `__file__` or evidence are changed. The only allowed
predecessor is an immutable `cold_cycle_v3` restoration archive whose actual
phase is `gdn-prework-serving`; both journal and independent restoration-audit
SHA references must be supplied. The preceding numerical status does not stand
in for restoration, and no current service PID is hardcoded.

After the root has closed and independently audited that real predecessor:

```sh
.venv/bin/python -I -B bench/m5_ultra_256gb/route_http_formal/preregister.py --prepare \
  --predecessor /absolute/archive/restored-journal.json --predecessor-sha256 JOURNAL_SHA \
  --restoration-audit /absolute/archive/restoration-audit.json --restoration-audit-sha256 AUDIT_SHA
```

The builder writes `prereg-formal-v2/{owner-plan,preparation,commands}.json` and
small frozen-source copies. It performs no model payload hash or service action.
Root then executes the saved `cpu_prepare` and `readonly_service_prepare`
commands; `--seal-receipt` binds their real PREPARED evidence. The resulting
receipt contains `owner_plan_sha256`, `prepared_journal_sha256` and `source_pins`.
The saved `execute` command runs `execute.py --run` only after that receipt
exists. It rechecks its own source pin, controller, owner, plan, and exact
PREPARED journal bytes before stop. Owner invocation receives only the existing
`--plan --plan-sha256 --out` contract. Finally recovery follows any changed
service state; an unknown owner launch with no directory cannot become
`--no-experiment`. The registration command does not execute these actions.

The first actual guarded registration failed before any service change: its
source-pin loop overwrote the plan digest used by saved commands. The original
`prereg-formal-v1` and `route-http-formal-v1-registration` evidence remain
unchanged. V2 uses independent `plan_digest` and `source_digest` variables, fresh
output paths, and two regression tests that execute actual commands/preparation
writes and receipt sealing against temporary metadata. Six whole CPU modules
now contain 64 tests; mocked validation does not grant device qualification.

Actual runs repeat the original 157-entry native preflight and all model-file
hash/stat checks before and after. Extra adapters use
`frozen-adapters/<absolute-source-path-without-leading-slash>` plus
`adapter-pins.json`, avoiding collisions between original and new `formal.py`.
Outer PID/listener receipts retain the original three fields; inner runner
receipts have four. Auditing does not invent an outer stderr field.

`audit_restore.py --journal CLOSED --out NEW.json` is independent of experiment
success. `audit_formal.py --owner CLOSED --journal CLOSED --plan-sha256 SHA --out
NEW.json` rechecks the actual wire counts, POST-to-DONE latencies, common request
window, all twelve process points, source/runtime/model receipts, direct-child
reaps, raw resources and restoration. Resource filename ordering supports
indices beyond 999. Paired ratios are adjacent process comparisons; three-process
medians are not pooled request percentiles. No performance is inferred from
qualification durations or missing points.
