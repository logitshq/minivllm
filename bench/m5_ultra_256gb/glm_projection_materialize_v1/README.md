# GLM projection materialization — unexecuted, default OFF

A small injected loader wrapper, not a new loader implementation. No backend is imported, no file is read and no device is touched on import or `build(..., enabled=False)`. It does not install patches or provide a standalone device CLI. Source and seven CPU mechanism tests are prepared; **none has been run** during E055.

With explicit enablement, `build(original_load, mx, tree_flatten, admit=…, emit=…)` returns a callable. The caller must supply the exact owned, source-pinned `mlx_vlm.utils.load` and an admission callback that verifies the original62-shard checkpoint/config/runtime, official source chain, no custom quantization/offload, and the current registered cold owner. This prototype has no device admission or lifecycle integration; an arbitrary callback is not such proof.

The wrapper requires the original local GLM checkpoint, default eager caller semantics, strict loading, no adapter, no offload_index.json and no extra loader options. It calls the unchanged official loader **once** with `lazy=True, strict=True, trust_remote_code=False`. All official sanitizer arithmetic, numeric expert order, quantization aliases, MTP and vision handling remain untouched. Public `load` returns only after its `load_model` frames and weight dictionaries are gone; the wrapper then materializes final model parameters before returning the same model/processor tuple. Processor construction happens before weight materialization in this arm, unlike the original eager path; its errors propagate with no fallback.

The final parameter namespace is `language_model.model.layers.3…44.mlp.switch_mlp.PROJ.{weight,scales,biases}`, plus `language_model.mtp.0.block.mlp.switch_mlp.PROJ.…`. A complete preflight checks all129 projection groups, their original U32/F16 shapes, no leftover `.experts.` or unexpected switch tensors, and every remaining parameter. Group order is numeric layer, then original gate/down/up, then weight/scales/biases; remaining keys each get one group. All final parameter keys are covered once.

Each group evaluates, synchronizes, drops its temporary handle list, and clears retired cached buffers. Final model-owned outputs remain intact. The maximum group payload is1,660,944,384B; this is **not** a physical memory bound. Scalar records contain no arrays. MLX lazy dependency retirement, page-cache behavior and model residency have not been measured. No allocator/wired limit or IO policy changes are made.

Keep the official later `materialize_lazy_state` call intact: it also covers plain-helper and underscore buffers outside `model.parameters()` and uses8-array chunks. Keep later official gate/up fusion intact. Our wrapper must run on the existing MLX executor, before returning to the ordinary EnginePool path. A changed wrapper must not reuse the previous probe's claim that the inner official call used `lazy=False`; a new route identity and recorded inner `lazy=True` boundary are required.

Prepared CPU tests cover inert OFF, exact final key/group order and identities, malformed shapes/missing MTP/extra experts, payload bound, strict options/offload refusal, a mocked original loader's dictionary lifetime, and evaluation failure without retry/completion. They deliberately do not claim MLX graph retirement or numerical equivalence. Existing E036 fake sanitizer tests and E041 tiny actual file-like smoke remain separate evidence.

After source review and CPU execution following E055 closure, require a tiny actual original-stack byte/retirement qualification, then a bounded real-projection byte check before a new cold full-load registration. Preserve existing zero-swap, 220/240GiB sampled policies and settled service recovery; no result here grants fit, inference correctness or speed.
