# 01 模型前向：最简单但正确的 Qwen3.5 / Qwen3.8 实现

日期：2026-10-13。目标：用 MLX 写出 Qwen3.5 架构（Qwen3.8-27B 用的就是它，config 里 `model_type = qwen3_5`）的前向，
**没有 cache、没有 batch、没有自定义 kernel**，每生成一个 token 就把 prompt 加已生成的全部重新算一遍。慢，但只有这样才能把"模型算对了"和后面"cache 算对了"分开验证。

引擎里只 `import mlx`。

## 架构速记（Qwen3.5 和普通 Qwen3 的四个不同）

1. **24 层里 18 层是 Gated DeltaNet，只有每第 4 层是全注意力**（27B：64 层里 48 层 GDN、16 层注意力）。GDN 是线性注意力：没有 KV cache，每个头维护一个 Dk×Dv 的状态矩阵 S，逐 token 递推：
   `S = S·exp(g) ; S += k ⊗ (v − kᵀS)·β ; o = qᵀS`。g 是衰减（永远 ≤ 0），β 是写入强度，都由当前 token 算出来。进递推前 q/k/v 先过一个 kernel 为 4 的深度可分离因果卷积。
2. **RMSNorm 是零中心的**：`y = norm(x)·(1 + w)`，权重初始为 0。GDN 输出的门控 norm 不是零中心：`y = norm(x)·w·silu(z)`。
3. **注意力带输出门**：q_proj 输出两倍宽，每个头的前 256 维是 q、后 256 维是门，最后 `o * sigmoid(gate)`。
4. **RoPE 只转 head_dim 的 1/4**（256 里的 64 维），theta 1e7。原版是三路 mrope（时间/高/宽），纯文本三路位置相同，数学上就是普通 RoPE。fp32 逐 token 对上 HF 证明了这一点。

## 验证结果

| 档 | 对比对象 | 结果 |
|---|---|---|
| fp32 | HF transformers fp32 | logits 最大差 **0.0001**（logit 量级 32），48 个 greedy token **逐个相同** |
| bf16 | HF transformers bf16 | prompt 每个位置 argmax 相同，logits 差 0.75；greedy 第 12 个 token 分叉后又合上（mlx-lm 也是第 12 个） |
| nvfp4 0.8B | mlx-lm 同一 checkpoint | 量化 GEMM 逐位相同；整模型 logits 差 1.06，greedy 对 10 个 |
| **nvfp4 27B** | mlx-lm 同一 checkpoint | **24 个 greedy token 逐个相同** |

fp32 对 fp32 才是正确性的证据。bf16 跨框架分叉是正常的：两边矩阵乘的累加顺序不同，top-1 和 top-2 很接近的位置就会翻。

## 踩的坑

- **mlx-community 的 checkpoint 把零中心 RMSNorm 的 +1 烧进了权重**（存的是 1 + w，这样它们可以直接用标准 RMSNorm），GDN 的普通 norm 不动。我们的 loader 读 mlx 格式时要减回去。症状：bf16 对 HF 完美，nvfp4 却全盘错；逐层对比发现 `input_layernorm` 输出差 6 到 20。
- 27B 的 mlx 版权重名和 0.8B 不同：视觉塔叫 `vision_tower.*`，lm_head 在 `language_model.lm_head.*`（27B 不绑定词表）。
- transformers 5 的 `apply_chat_template(return_tensors=...)` 返回 BatchEncoding。
- `mx.fast.rms_norm` 算的是 `norm(x)·w`，零中心要传 `1 + w`。

## 速度（没有 cache，仅作记录）

| 模型 | 生成 | 耗时 |
|---|---|---|
| 0.8B bf16 | 16 token | 1.2 s |
| 27B nvfp4 | 24 token | 8.3 s（约 3 tok/s，每个 token 重算整句） |

每个 token 重算整句，复杂度 O(T²)，prompt 一长就不可用。第 2 步加 KV cache 和 GDN 状态槽，目标是 decode 一步只算一个 token。

## 依赖原则（这一步定下来的）
