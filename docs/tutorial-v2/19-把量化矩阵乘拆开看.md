# 19：把量化矩阵乘拆开看

这一章沿着“原算子→手写同几何控制→只改几何”的顺序研究一次量化矩阵向量乘。V22数值通过，但收益门未过，结果没有进入引擎。它与上一章的投影拼接是两项独立实验。

## 1. 先保留真正的baseline

原Linear把BF16输入交给MLX量化算子：

```python
# before：真实A路径，不能用手写R4替它计收益
y = mx.quantized_matmul(x, weight, scales, transpose=True,
                       group_size=16, bits=4, mode="nvfp4")
```

这次只选层0 MLP gate：x[1,5120]，weight为U32[17408,640]，scales为U8[17408,320]。通过safetensors header定位两个tensor，再映射所需range并复制脱离映射，没有加载27B整模型。

每个U32装8个4bit值，所以5120/8=640；每16个值共享一个U8 E4M3 scale，所以5120/16=320。改变线程处理多少输出行，不改变这两个存储形状。

## 2. 把每一行的K方向工作数清楚

输出一行是5120个输入与解码权重的点积。MLX fast QMV让一个32-lane SIMD共同完成它：

```text
每lane每轮：16个连续输入值 = 1个量化组
每SIMD每轮：32 × 16 = 512列 = 32个量化组
每行共：5120 / 512 = 10轮，合计320个量化组
```

每lane内部把4个FP32乘积组合起来，再依次累加四个这样的子组，乘这一组的scale；十轮结果依次累加，最后simd_sum并写BF16。FP4 E2M1与scale E4M3的原decode类型保留。

下面是官方fast_impl控制流的教学节选，具体类型、指针和qdot表达式见[原型参考包](../experiments/19-nvfp4-qmv/README.md)：

```cpp
for (int k = 0; k < in_vec_size; k += 512) {
  load_vector<T, float, 16>(x, x_thread);
  for (int row = 0; row < R; row++) {
    float s = dequantize_scale<float, 16>(row_scale[row]);
    result[row] += qdot<float, 16, 4>(row_weight[row], x_thread, s);
  }
  // 原实现推进weight/scales/x的指针。
}
// 各行独立simd_sum，最后static_cast<T>写回。
```

## 3. 先做R4控制，再改R2

M4原fast路径每个SIMD算4行，两个SIMD构成一个64线程group，因此每组8行。17408/8=2176组。

R2只把每SIMD行数4改为2，同一个group算4行，17408/4=4352组。每行仍由相同32 lanes跑同样十轮；权重总量和量化组都没有变化。更多组和较少独立行累积可能改变调度/寄存器压力，也会增加输入重读，收益必须实测。

```python
# after的第一步：R=4，先证明手写入口复现原算子
# after的第二步：R=2，只改变每SIMD输出行数
y = kernel(inputs=[weight, scales, x],
           template=[("T", mx.bfloat16), ("R", R)],
           grid=(64, 17408 // (2*R), 1), threadgroup=(64, 1, 1),
           output_shapes=[(1, 17408)], output_dtypes=[mx.bfloat16])[0]
```

wrapper调用官方原fast_impl，省略资格检查的关键部分如下：

```cpp
constant int v22_in_vec_size = 5120;
constant int v22_out_vec_size = 17408;
// 下列位于kernel body；constant引用不能由device数组参数冒充。
uint local = thread_position_in_threadgroup.x;
uint3 tile = uint3(0, threadgroup_position_in_grid.y, 0);
fp_qmv_fast_impl<T, 16, 4, false, R>(weight, scales, nullptr, x, output,
    v22_in_vec_size, v22_out_vec_size, tile, local / 32, local % 32);
```

grid.x=64且threadgroup.x=64，只有一个x方向group；tile.x显式为0，避免把线程编号误作输入向量编号。官方完整头文件还依赖无关GEMM定义，原型仅把所需fp4/fp8、helper与fast_impl逐段原样展开并记录SHA，保留MIT许可。

[MLX0.32.3源码](https://github.com/ml-explore/mlx/blob/v0.32.3/mlx/backend/metal/quantized.cpp#L435-L503)对M5 Max大N已有R2选择；它提供一个具体假设，不能直接证明M4应该更快。Lithos也有每SIMD行数配置，但其pack和算术不同，本实验没有移植。

## 4. 同公式也先过资格

JIT入口、编译上下文和循环展开可能与builtin不同。即使公式逐字相同，也不能跳过R4控制，把差异都解释为几何改变。

先对8个synthetic与1个历史真实L0输入做9项R4-vs-QMM比较；finite、shape、dtype和每个BF16 byte都必须相同。全部通过后才首次调用R2，再对同9输入分别比较QMM与R4，共18项。

本次27项全部通过，Metal编译成功。它只覆盖这些有限样本；没有新增全模型、所有输入、cache/lifecycle或E2E资格。真实x来自旧V17首次normal decode，计时仍只使用8个synthetic。

## 5. 把启动成本放在计时之外，也保留它

| 首次调用host wall | 原QMM | R4 | R2 |
|---|---:|---:|---:|
| 含编译/准备/执行 | 5.483916ms | 122.476541ms | 44.466667ms |

这些不是纯编译时长，也没有被藏进正式block。稳态比较每块相同prime128/repeat512，每次eval所有17408个输出，整对完成后才转CPU/hash。

固定前AA/BB、六个AB/BA、后AA/BB。AA=0.999156080/1.013800621，BB=1.006487403/1.004035520；两类各两个控制均保留并通过严格位置门。

## 6. 正确和控制通过，仍然停止

| Battery局部调用 | A原QMM | B手写R2 |
|---|---:|---:|
| 六对host wall中位 | 231.091267578μs | 230.599812500μs |

降低0.212667092%，5/6对B更快，保留另外一对负结果。跑前门要求至少5%且5/6胜，第一项未达，原结论为`STOP-MICRO-GATE`；不能把这0.21%描述成稳定kernel收益，也不据此推断完整引擎表现或排除其他GPU几何收益。

24份快照电量均26%、Battery、thermal0、pressure1、SO/SI/PO/Compressions增量0、Decompressions+5；child31181正常wait/reap exit2，两次外部strict absence通过。host wall不是GPU kernel timestamp；该电源域不混入AC或正式前沿。
