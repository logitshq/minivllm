# V78: FP32 scaled Q/K ready, CPU ready only

This independent probe extends the frozen V44 activated helper. It is not connected to an engine or native replay, and has no GPU result or performance harness. The public API remains already-activated BF16 `[1,10240]` plus read-only FP32 g/beta `[1,48]` and S `[1,48,128,128]`. The numeric harness materializes one external `nn.silu(saved u)` and shares it across A44/B78; the helper does not apply activation.

The first 16 prework threadgroups keep V44's BF16-to-FP32 raw Q/K loads, first threadgroup barrier, lane-0 ascending serial qn/kn loop, and rsqrt expressions byte for byte. Lane 0 additionally writes qs/ks to a two-float threadgroup array. A second barrier, reached uniformly by all 128 lanes in each Q/K group, makes those values available before each lane writes `q_ready = qs * rawq` and `k_ready = ks * rawk` to FP32 device outputs. The original global scales output remains diagnostic. The other 48 groups still copy V unchanged.

V44's source has left-associated `ks * rawk[d] * held[j]`, `ex * held[j] + ks * rawk[d] * delta`, and `qs * rawq[d] * s`. V78 stores each first FP32 product in prework, then uses `k_ready[d] * held[j]`, `ex * held[j] + k_ready[d] * delta`, and `q_ready[d] * s`. The state source differs only by removing local qs/ks loads and those three substitutions. held32, split4, ascending 32-term K loops and split merges, exp/beta/delta, canonical S/o stores, barriers, geometry, HEADER, and `math_mode=safe` are preserved. The reverse-source proof is exact; it proves the edit boundary, not device numerical equivalence.

This moves an FP32 materialization boundary. Source associativity alone does not prove the old compiler's intermediate rounding or FMA/contraction choices. No BF16 normalized-Q/K rounding is introduced. The idea is related to normalized-Q/K preprocessing elsewhere, but this helper is derived from the locally pinned V44 source. Actual strict local validation is required; a later local PASS would still not establish full-engine equivalence or a speed gain.

The new PSOs are `gdn_activated_scaled_ready_prework_v78_build1` and `gdn_scaled_ready_cached_state_v78_build1`. The state retains the unused scales input binding, so declared input order is unchanged and expected S/S_new slots remain 6/9. They are not GPU-observed here. A future native integration must explicitly whitelist this new state PSO at the actually verified slots; V40's identity must not be reused. No native files or whitelists are changed.

`numeric.py` defaults to stdlib source/bank hash verification and imports neither MLX nor NumPy. Only explicit `--execute-gpu --out /absolute/new/path` enables a later local qualification under the frozen MLX 0.32.3/M4 Max controls. It compares the real public V44 and V78 two-kernel paths over the same 9 historical real plus 6 synthetic saved banks, without feedback into S. Gate: 30 strict finite FP32 raw-byte o/S checks, 30 strict q_ready/k_ready checks against a separate safe Metal probe applying original-order `qs * rawq`/`ks * rawk`, 30 diagnostic V/scales byte checks, and 15 before/after read-only bank/activated/ready checks. Signed-zero bits are preserved. Qualification repeats prework for diagnostics, so its duration and dispatch count are not performance evidence. The first failure stops and preserves A/B bytes plus truthful completed counts.

CPU reproduction: `python3 -B check_cpu.py`, then `python3 -B numeric.py`. `source-proof.json`, `source-pins.json`, and `CPU-READY.json` record the frozen source boundary and CPU checks. The full upstream MLX MIT notice is retained in `LICENSE-MLX-MIT`.
