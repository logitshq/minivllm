M5 Ultra 256 GiB 实验记录

结论：完整模型正确性 PASS；V19 的端到端结果 DO_NOT_ADOPT，继续默认关闭。
C4 总吞吐在本次固定负载下领先 oMLX，但所有并发级别的客户端交付速度均落后，不能宣称整体胜出。

机器：Apple M5 Ultra，80 GPU cores，256 GiB，macOS 27.0.1，AC Power。
模型：mlx-community/Qwen3.8-27B-nvfp4 @ 5ff8ef173ad0d7c3aae92f0be43031a6ab8067c6；BF16 activations。
运行时：Python 3.13.16；MLX/MLX-Metal 0.32.3；官方 oMLX 0.7.1.dev1。
源码：handoff 559ced1；M5 decode 实验 84c4659；本地分支 experiment/m5-ultra-256gb。

正确性：accepted/OFF/ON/reset-OFF，4×32 输出，128 份 logits 原始文件逐字节一致，16,384 个状态签名严格相等，18 个 fallback 通过。
accepted 的 compiled gates 也与原始未编译路径全部 32 步的 logits/状态严格一致。1,349 个参数的 key/shape/dtype 跨 worker 相等，object ID 仅进程内比较。

V19 内部端到端：6 个新进程，顺序 OFF/ON/ON/OFF/OFF/ON，每进程 3 warm + 3 measured。
三组吞吐变化：+1.5223%, +2.6309%, -2.7957%。
aggregate y +2.4593%；aggregate x +2.2653%。第三组为负，未达到预先规定的全部三组正收益要求。

官方对照：每个并发级别 3 组 fresh pair；18 个进程、252 个请求、8,064 个输出 token（包含 warm）。
值为 median(3 process medians)，每个 process median 来自 3 个测量 group。
